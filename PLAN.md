# Spider Pomodoro — plan

A pomodoro timer with an original spider hero who hangs from the top of the screen on a web line.
Same timer on Mac and iPhone, synced through iCloud.

## Decisions so far

| Topic | Choice |
|---|---|
| Hero art | Original spider hero (our own design, not Marvel's Spider-Man) |
| Sync | iCloud (CloudKit), paid Apple Developer account available |
| iPhone | Dynamic Island + Lock Screen (Live Activity), home screen widget |
| Mac | Menu bar timer + hanging hero on desktop, desktop widget |
| Default timer | 25 min work, 5 min break, 15 min long break after 4 rounds (changeable in settings) |
| Apple team | T25NT3U739 (paid, Individual) |
| App ID | `com.mertcankarabas.spiderpomodoro` on both iPhone and Mac; widgets add `.widgets` |
| Shared storage | App Group `group.com.mertcankarabas.spiderpomodoro` |

## How it looks

- **Work starts:** hero at top, web line short.
- **Work goes on:** web line grows, hero slowly drops down. Position = how much time is gone.
- **Break:** hero climbs back up the web.
- **Phase ends:** sound + notification on both devices, hero waves.

## How it works

### One shared timer state

We never sync a ticking clock. We sync one small record:

```
phase        work | shortBreak | longBreak
startedAt    date the phase started
duration     seconds
pausedLeft   seconds left if paused, else empty
round        1...4
updatedAt    date of last change (newest wins)
```

Each device computes "minutes left" from `startedAt + duration - now`.
So Mac and iPhone always show the same number, even offline, and only need to talk when you press start, pause or skip.

### Sync (iCloud)

- Record lives in your private iCloud database (CloudKit).
- When one device changes it, iCloud sends a silent push to the other device.
- That device saves the new state, refreshes its widgets and updates the Dynamic Island.

Each device stores when the last button press happened and on which device (a random ID, not its name).
On every check, the newer side wins; an exact tie goes to the server copy so all devices agree.

Known limits (Apple rules, not bugs):
- If you start the timer on Mac, the iPhone widget usually updates within seconds, but iOS can delay it when the iPhone is asleep or in Low Power Mode.
- iOS does not let an app start a Dynamic Island timer from the background without our own push server. Version 1: Dynamic Island starts when you start on iPhone or open the iPhone app. Later option: small push server so a Mac start also starts it on iPhone.

### Apple pieces we use

| Piece | Used for |
|---|---|
| SwiftUI | All screens and the hero drawing |
| WidgetKit | Home widget (iPhone) and desktop widget (Mac) |
| ActivityKit (Live Activity) | Dynamic Island + Lock Screen on iPhone |
| App Intents | Start / pause / skip buttons inside widgets |
| CloudKit | Sync between devices |
| App Group | Share state between app and its widgets |
| NSStatusItem + transparent window | Mac menu bar timer and hanging hero |
| Darwin notifications | Tell the app when a widget button changed the timer (same device) |
| User Notifications | Sound + alert when work or break ends |

Widgets cannot run animations all the time. Two tricks:
- Countdown text and progress bar use Apple's built-in live timer views, so they tick every second for free.
- Hero position is pre-planned once per minute in the widget timeline, so the hero still drops down slowly.

The Mac hanging hero is a normal app window (transparent, always on top, clicks pass through), so it can animate smoothly and swing a little.

### Hero art

Drawn in code with SwiftUI shapes (`Packages/SpiderCore/Sources/SpiderCore/Hero/`), so it stays sharp at any size.
Look: red mask with big slanted white eyes, navy suit, gold spider badge and belt, red gloves and boots, big cartoon head.
Poses: hanging (work), climbing (break), waving (phase done, or break waiting), sleeping (timer off).
Our own look and colors, so it is safe to share or put on the App Store later.

On Mac, the hanging hero uses Core Animation layers: swinging, dropping and the small flip-book
animations run inside macOS, so the app only checks the timer twice a second.

## Project layout

```
project.yml                  Xcode project definition (run `xcodegen generate` after editing)
SpiderPomodoro.xcodeproj     generated, don't edit by hand
Packages/SpiderCore/         shared timer logic, hero drawing, widget timeline + tests
Mac/                         Mac menu bar app (+ Info.plist, entitlements generated by XcodeGen)
iOS/                         iPhone app
Widgets/                     widget and Live Activity views shared by iPhone and Mac
                             (button intents live in SpiderCore so app and widgets share one type)
iOSWidgets/, MacWidgets/     per-platform widget Info.plist and entitlements (generated)
```

Minimum versions: iOS 18, macOS 15 (built with Xcode 27.2).

## Run it

```
cd Packages/SpiderCore && swift test          # timer tests
xcodegen generate                             # after changing project.yml
open SpiderPomodoro.xcodeproj                 # then pick SpiderPomodoroMac and press Run
```
